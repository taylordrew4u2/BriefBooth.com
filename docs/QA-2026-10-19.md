## Fixed

Four asynchronous actions could leave busy controls stuck if their backend promise rejected rather than returning an error result:

- Add a consultation.
- Save weekly availability.
- Save a recovered password.
- Cancel a booking or pending request.

Each now releases busy state in `finally` and reports an actionable error. An ambiguous consultation-creation or cancellation failure asks the user to check the stored state before retrying. A failed action does not announce success or redirect to the studio.

`tests/async-actions.mjs` executes the actual handler functions with failing and successful backend calls. It checks busy-state cleanup, feedback, absence of false success, and successful cancellation/recovery behavior. It is included in `npm test`. This is a focused handler test, not a browser integration test.

## Follow-up reliability fixes

- Payment preferences now update only payment fields; saving them cannot publish unrelated profile drafts.
- Timezone and consultation visibility saves verify a returned row, handle errors, and disable their buttons while saving. Missing rows no longer produce a false success message.
- Zoom status distinguishes loading, connected, disconnected, and lookup failure. A failed check offers retry and does not imply a stored connection was removed.
- Booking detail polling is serial, stops when the component is cleaned up or cancellation starts, ignores stale results, and clears refresh errors after recovery.
